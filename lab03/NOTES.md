git log --oneline --stat



Показывает историю коммитов в кратком виде и статистику изменений файлов: сколько строк добавлено и удалено.



git diff HEAD~2 HEAD -- lab03/calc.py



Сравнивает файл calc.py между коммитом двух шагов назад и текущим коммитом. Строки с + добавлены, строки с - удалены.



git show HEAD\~1



Показывает информацию о предыдущем коммите, включая автора, дату, сообщение и внесённые изменения. В моём случае коммит добавил вычитание в калькулятор.



git log -S"def" --oneline -- lab03/calc.py



Ищет коммиты, в которых изменилось количество вхождений текста def в файле. В моём случае команда ничего не вывела, потому что таких изменений не нашлось.



git blame lab03/calc.py



Показывает для каждой строки файла коммит, автора и дату последнего изменения строки.



git restore calc.py отменяет незакоммиченные изменения файла и восстанавливает его из индекса.

git restore --source=HEAD\~2 calc.py восстанавливает содержимое файла из коммита, который находится на два коммита раньше текущего.

git diff -- calc.py показывает отличия рабочей копии от текущего коммита.

Команда git restore --source=HEAD\~2 calc.py не перемещает ветку и не удаляет коммиты — она меняет только содержимое файла в рабочей копии.

git revert HEAD создаёт новый коммит, отменяющий изменения предыдущего коммита. Исходный коммит остаётся в истории.
git reset --hard HEAD~1 перемещает текущую ветку на предыдущий коммит и удаляет изменения из индекса и рабочей папки. Незакоммиченная работа может быть потеряна.
git revert безопаснее для отмены уже опубликованных изменений, поскольку сохраняет историю коммитов.

- Ветка — изменяемая ссылка на коммит, которая перемещается при создании новых коммитов.
- Тег — метка, указывающая на определённый коммит. Обычно теги используют для обозначения версий проекта, например v1.0.
- В этой работе тег v1.0 обозначает рабочую версию калькулятора без небезопасного деления.

git switch -c experiment создаёт новую ветку experiment и переключается на неё.
В ветке experiment добавлено безопасное деление: перед делением программа проверяет, что второе число не равно нулю.
git commit -m "Add safe division" сохраняет добавление безопасного деления в отдельном коммите.
git switch main переключает обратно на основную ветку main.
git merge --no-ff experiment объединяет изменения из experiment с main и создаёт отдельный коммит слияния.
git branch -d experiment удаляет ветку experiment после успешного слияния. Коммиты остаются в истории main.
git push origin main отправляет обновлённую ветку main на GitHub.
